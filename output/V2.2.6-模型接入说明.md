# 映词 V2.2.6 模型接入说明

## 本次修复

- 修订构建 11：修复截图中的 402 预估费用超额。OpenRouter 明确发送 `max_tokens`：聊天/识图测试 512，正常聊天及反推 4096。不会再因为软件未传此字段而默认请求 131072 tokens。实际余额不足、密钥限额或服务商限制仍可能返回 402。

- 截图中的 `https://openrouter.ai/api` 自动补全为 `https://openrouter.ai/api/v1`，读取模型和聊天走同一正确根路径。旧配置无需先删除或重新安装。
- 聊天连接测试只发送一条短文字；识图测试单独验证图片能力，互不冒充成功。
- 文字历史以字符串发送，带图消息才发送多模态数组，减少部分兼容服务拒绝纯文本数组的问题。
- Claude 官方接口转换为 Messages 请求，正确处理 system、多轮文本、图片和返回内容；模型列表支持有界分页。
- 保留真实服务错误，不自动替换模型、不转发密钥到另一服务商、不自动重试计费请求。

## 边界与注意事项

- 不能承诺“全网所有模型”都可用：仅支持 Responses、WebSocket、云平台 IAM、特殊签名、OAuth 工作区或其他专有协议的服务不在本版直接接入范围。网页会员不等同于 API 权限。
- 各平台对地区、额度、模型权限、上下文长度、图片输入的限制仍有效；安卓客户端无法绕过。
- 有的平台不公开兼容模型列表。读取失败时手动填写服务商给出的 ID，再点“测试聊天连接”。列表成功也不保证所有列出的模型都支持聊天。
- Claude 协议中转可填写完整 `/messages` 地址以选择原生消息格式；其他自定义路径仍按 OpenAI 兼容处理，保留原主机和路径。
- Claude 和 OpenRouter 单次正常回复上限为 4096 tokens，连接测试为 512，截断会显示失败，避免将不完整提示词或方案冒充完成。其他兼容服务不强加 temperature、max_tokens 等可能冲突的参数。
- 本次扩展是聊天和图片理解接口适配，不扩大现有生图协议范围。图片生成仍使用已配置的生图服务和原有适配。
- 不会发送用户密钥到开发者服务器。测试聊天和识图可能收费，均由用户手动触发。
- 直接覆盖安装，不要卸载旧版本，以保留本机收藏、对话、设置及加密密钥。
